# Cross-host Feature DAG Business Assistant Design

## 目标

提供一个面向业务人员的零本地运行环境依赖 Skill，辅助把函数式特征表达式整理为当前 Feature DAG 引擎可消费的模型特征配置。使用者只需要能够提供表达式、衍生特征名称、前台已有的 BASE 特征配置，以及最终完整模型 JSON；使用者不需要 Java、引擎源码或本地脚本环境。

同一份 Skill 同时打包为 ChatGPT/Codex 插件和 Claude Code 插件。第一版以规则镜像完成校验，并为以后接入远程真实引擎校验器和扩展算子契约保留稳定接口。

## 非目标

- 第一版不调用 Java 引擎，不声称执行了真实引擎初始化或运行时求值。
- 第一版不审计标准注册表是否完整注册全部 21 个标准算子。
- 不校验目标不可达的其他特征条目。
- 不校验 `catalog`、`encode`、`table_name` 等非引擎业务字段。
- 不根据特征名称猜测数据类型、实体域或序列最大长度。
- 不覆盖前台已经存在但值冲突的字段。

## 输入与前提

业务按流程提供以下信息：

1. 函数式特征表达式。
2. 目标衍生特征的 `name`；`store_name` 等业务字段仍由业务维护。
3. 表达式引用的 BASE 特征当前前台配置。
4. 必要时补充无法可靠推断的数据类型、实体域、默认值或序列最大长度。
5. 最终完整模型 JSON，顶层格式固定为：

```json
{
  "feature_set_name": "...",
  "version": "...",
  "features": []
}
```

## 交互状态与数据流

### 1. 表达式语法检查

第一阶段只判断表达式是否符合语法，不检查算子是否存在、是否注册、参数数量或类型是否正确。检查内容包括：

- 函数调用和嵌套调用；
- 左右括号、方括号和花括号；
- 参数逗号和对象冒号；
- 单引号与双引号字符串及支持的转义；
- 整数、小数、负数、布尔值和 `null`；
- 数组字面量、对象字面量和命名参数；
- 尾随内容、尾随逗号和未闭合结构；
- 最大嵌套深度 200。

语法失败时给出错误位置和附近片段，并停止后续 BASE 提取和配置推断。

如果表达式正文在字符串字面量外出现 Markdown 展示导致的 `\_`，Skill 必须先提示已发现展示转义，再仅对字符串外的 `\_` 生成规范化副本并进行校验。原始表达式和规范化表达式都要保留在对话中，不能静默改写字符串字面量。

### 2. BASE 引用提取

语法通过后，按 AST 语义提取特征引用，并按首次出现顺序去重：

- 函数名不是特征引用；
- 对象 key 和命名参数名不是特征引用；
- 字符串、数字、布尔值和 `null` 不是特征引用；
- 函数参数、数组元素和对象 value 中的裸标识符是特征引用。

以 `features[].name` 作为特征身份，不使用 `raw_name` 代替。随后请业务一次性提供所列 BASE 的当前前台配置。

### 3. BASE 配置补齐

Skill 按每个 BASE 独立维护三类结果：

- 已完整：字段存在且符合表达式约束；
- 待补充：字段缺失、为空字符串或为 `null`，且值尚未明确；
- 存在冲突：字段存在，但值不符合表达式或引擎契约。

需要检查和按需补充的核心字段包括 `definition_type`、`type`、`value_shape`、`entity_scopes` 和 `seq_max_length`。`name` 和可用状态同时参与检查。`dft` 不作为强制字段；如果业务提供或现有配置包含默认值，则校验其与 `type`、`value_shape` 是否兼容，缺失时只有在业务明确希望配置回退值后才生成新增属性。

表达式只能提供约束而不总能确定实际值。例如作为 `slice_by_indices` 第一参数时必须是序列，但无法仅由表达式判断元素究竟是 `STRING`、`INT` 还是其他类型。无法可靠确定的值必须向业务询问，不能从特征名称猜测。

字段已经存在但冲突时，只输出当前值、要求值、冲突依据和手工修改提示；不得为同名字段生成覆盖用新增属性。字段缺失且值已确认时，按前台新增属性数组输出。循环处理直到所有可达 BASE 已完整，或明确报告仍缺少的信息。

### 4. 衍生特征配置

衍生特征名称由业务提供。Skill 根据已确认的 BASE 元数据和算子契约推断以下字段，并只为当前衍生条目中缺失的字段生成前台新增属性：

- `definition_type = DERIVED`；
- 原始或已明确规范化的 `expression`；
- `output_policy = OUTPUT`；
- 输出 `type`；
- 输出 `value_shape`；
- 输出 `entity_scopes`；
- 输出 `seq_max_length`。

当算子契约能够从输入最大长度得到输出安全上限时，可以自动填写 `seq_max_length`；不能可靠得到时必须询问业务。衍生 `dft` 与 BASE 一样保持可选，只在业务明确需要且值已确认时生成。

### 5. 最终完整模型校验

业务提供完整模型 JSON 后，Skill 只校验目标衍生特征的可达子图：

1. 按业务提供的目标名称定位唯一目标条目。
2. 解析目标表达式并收集引用。
3. 引用另一个 `DERIVED` 时递归解析其表达式。
4. 引用 `BASE` 时停止递归。
5. 使用 DFS 三色状态检测可达依赖环。
6. 校验可达范围内的缺失引用、重复定义、禁用特征、字段冲突和已知算子契约。

目标及可达依赖之外的 `features[]` 条目完全跳过；相关条目中的非引擎业务字段也跳过。目标或可达依赖存在同名重复定义时，由于无法唯一解析，必须判定不通过。

## 前台新增属性输出契约

每个 BASE 和衍生特征分别输出一个 JSON 数组。数组元素固定包含：

```json
{
  "raw_name": "seq_max_length",
  "data_value": 1,
  "data_type": "NUMBER",
  "default_value": "",
  "required": "true"
}
```

前台只支持四种 `data_type`：

| `data_type` | `data_value` 表示 |
| --- | --- |
| `NUMBER` | JSON 数字，不加引号 |
| `LIST` | 包含序列化列表的 JSON 字符串，例如 `"[\"USER\"]"` |
| `STRING` | JSON 字符串 |
| `BOOLEAN` | 字符串 `"true"` 或 `"false"` |

所有新增属性的 `default_value` 固定为 `""`，`required` 固定为字符串 `"true"`。当前协议不能表示对象类型的新增属性；遇到必须新增但值为对象的字段时，报告前台协议不支持，不伪造格式。

表达式作为 `STRING.data_value` 输出时，必须生成合法 JSON，正确转义表达式内部的双引号和反斜杠。

## 固定响应结构

### 表达式阶段

```text
语法校验：通过 / 不通过
错误位置：仅失败时提供
BASE 特征：按首次出现顺序列出
下一步：明确业务需要提供的内容
```

### 特征补齐阶段

```text
特征：<features[].name>
状态：待补充 / 存在冲突 / 已完整
需要业务回答：...
现有字段冲突：...
新增属性：[...]
```

没有新增属性时不输出虚假的占位数组。一个特征缺少多个字段时，在同一个数组中输出多个元素。

### 最终报告

```text
校验结论：规则校验通过 / 不通过 / 信息不完整
目标特征：...
校验范围：目标特征及其可达依赖
错误或冲突：...
未校验范围：无关特征、非引擎字段、真实数据运行时行为、标准算子注册完整性
```

第一版的通过结论必须写为“规则校验通过”，不得写成“真实引擎校验通过”。

## 算子契约与升级方式

`references/operator-contracts.md` 为独立的算子语义参考。每个契约记录：

- 算子名称；
- 参数数量；
- 每个参数的类型与形状约束；
- 输出类型与形状；
- entity scope 传播方式；
- `seq_max_length` 安全上限传播方式；
- 不能静态检查、只能在真实数据运行时发现的条件。

第一版在参考文件中记录当前 21 个标准算子的语义契约，但不执行“引擎注册表是否完整注册这 21 个算子”的全集审计。遇到不存在契约的函数时：

- 初始语法仍可通过；
- 不直接宣称它是非法算子；
- 类型、形状和长度推断标记为信息不完整；
- 提示需要新增算子契约；
- 不生成未经确认的衍生属性。

新增算子只需要在该参考中增加同结构契约，不修改主交互流程。

## 远程真实引擎校验扩展

`references/validator-extension.md` 定义未来可选校验工具的稳定输入：

```json
{
  "target_feature": "derived_feature_name",
  "feature_set": {
    "feature_set_name": "...",
    "version": "...",
    "features": []
  }
}
```

工具输出至少区分 `PASS`、`FAIL` 和 `INCOMPLETE`，并为每个问题返回阶段、特征名、字段、消息和可选错误位置。

当宿主提供该工具时，Skill 优先调用远程真实引擎校验器，并明确标注真实校验结果；工具不可用时回退到规则镜像流程。连接器不可用或调用失败时不得把规则校验伪装成远程成功。

## Codex 与 Claude Code 双宿主打包

插件使用一份 Skill 内容和两个宿主清单：

```text
feature-dag-business-assistant/
├── .codex-plugin/
│   └── plugin.json
├── .claude-plugin/
│   └── plugin.json
└── skills/
    └── configuring-feature-dag-models/
        ├── SKILL.md
        ├── agents/
        │   └── openai.yaml
        └── references/
            ├── expression-grammar.md
            ├── feature-fields.md
            ├── operator-contracts.md
            ├── output-contracts.md
            └── validator-extension.md
```

共享 `SKILL.md` frontmatter 只使用两个跨宿主字段：`name` 和 `description`。核心行为全部写在共享 Skill 和引用中，不写进宿主清单或 `agents/openai.yaml`。

- `.codex-plugin/plugin.json` 提供 ChatGPT/Codex 插件身份和 `./skills/` 路径。
- `.claude-plugin/plugin.json` 提供 Claude Code 插件身份和同一个 `./skills/` 路径。
- `agents/openai.yaml` 仅承载 ChatGPT/Codex 界面元数据。
- 第一版不声明脚本、Java、Python、Node、MCP 或其他运行环境依赖。
- Codex 显式调用名为 `$configuring-feature-dag-models`；Claude Code 显式调用名为 `/configuring-feature-dag-models`。

两个宿主各自使用其官方清单校验和安装方式；发布目录或团队 marketplace 元数据可以分开维护，但不能复制 Skill 正文。

## 错误处理边界

- 语法错误：停止后续阶段，给出位置和附近片段。
- BASE 配置未提供：列出仍缺少的特征，不继续生成衍生属性。
- 字段值未知：提出具体问题，并说明表达式只能推出的约束。
- 现有字段冲突：只报告和要求人工修改。
- 前台类型协议无法表示：标记信息不完整，不输出错误 JSON。
- 未知算子契约：标记需要扩展，不伪造推断。
- 远程工具失败：报告工具失败并回退到规则校验，分别标注两者边界。

## 验证策略

Skill 开发遵循 RED-GREEN-REFACTOR：

1. 在 Skill 编写前，使用已获授权的隔离子代理运行真实业务场景，记录无 Skill 时的错误、遗漏和输出格式偏差。
2. 编写最小 Skill 和必要引用，针对已观察到的失败提供正向输出契约。
3. 使用同一批隔离场景加载 Skill 重跑，比较引用提取、追问、冲突处理和输出 JSON。
4. 对新暴露的问题做最小修正并重测。

行为场景至少覆盖：

- 缺括号、缺逗号和未闭合字符串；
- 示例长表达式提取六个去重 BASE；
- 单个 BASE 缺少多个字段；
- 已有字段冲突时不生成覆盖项；
- `NUMBER.data_value` 为 JSON 数字，`LIST.data_value` 为包含序列化列表的 JSON 字符串；
- 衍生类型、形状、scope 和最大长度推断；
- 完整模型忽略无关错误配置；
- 可达依赖错误、重复定义和依赖环；
- 未知算子返回信息不完整；
- 无远程校验器时不声称真实引擎通过。

结构验证包括：

- Skill frontmatter、名称、引用链接和未完成占位符检查；
- `.codex-plugin/plugin.json` 校验；
- `.claude-plugin/plugin.json` 校验；
- 两个宿主清单指向同一个 `skills/`；
- 无脚本或本地运行环境依赖；
- 仓库要求的 `./scripts/run-self-test.sh` 保持通过。
