# 第一轮输出构建优化

## 实现范围

- `FeatureValueCollections.singleton` 改用允许 null 的 `Collections.singletonList`，减少单元素输出的列表、数组和包装对象。
- 公共 `GenerateResult` 构造器继续防御复制；新增包内 `fromOwnedEncodedValues`，只接收引擎独占的结果容器和编码器已经冻结的值。交付时冻结共享 Map、各候选 Map 和候选行列表，避免再次复制值列表和 Map 条目。
- 初始化时按目标输出实体域计算共享/候选输出 Map 的容量。仅用于预分配提示，实际输出路由仍由运行时句柄决定。
- 公共 Map 复制也按已知输入大小预分配；不改变键、元素和遍历顺序。

内部交付入口覆盖在线单请求、在线分组 Batch 和离线单行。离线 Batch 的结果类保持原有复制路径，只享受单元素列表与容器预分配优化。没有修改逻辑 DAG、物理规划、运行时或算子。

## 所有权与兼容性

内部交付入口不是面向调用方的免复制 API。其调用者必须拥有共享 Map、可变候选行列表和候选 Map 的独占所有权，且编码值已经不可变；交付后不能再修改这些容器。引擎在输出编码结束时调用，结果构建后不再修改相应容器。

序列/事件/嵌套 Map/List 的物化和冻结仍由现有编码器完成。公共构造器仍对调用方的 Map/List 做原有防御复制，原有嵌套元素语义不变。不会因为列表允许 null 而改用拒绝 null 的 List.of。

## 功能验证

新增独立 JUnit 4 `OutputConstructionTest`，覆盖公共构造器输入隔离、键顺序和 null 元素、单元素输出不可修改、嵌套事件数据冻结、修改原始数据及执行后续请求不污染既有结果、空候选、序列补齐、在线单请求与分组 Batch 等价、离线单行与 Batch 等价，以及并发请求隔离。

`mvn -q test` 通过，共 268 项。显式执行 `scripts/run-self-test.sh`，在冻结的存量注册表断言处失败：`Expected 23 operators, got 24`；失败与改动前相同，没有修改该冻结文件，因此完整自测脚本仍不算绿。

## 性能验证口径

以本轮开始时的工作区编译产物为 before，而不是 Git HEAD（工作区已有用户修改）。before/after 类文件分别固定在 `target/output-round1-before/classes` 和 `target/output-round1-after/classes`；独立 JVM 使用相同依赖、`-Xms4g -Xmx4g -XX:+UseG1GC`。

场景为 320 BASE + 320 DERIVED，160 条长度 730 的序列，每请求 300 货，4 并发，输入池 4，商品参数基数 300。每轮 1,000 次主线程预热，正式 10,000 次请求。计时轮不开 JFR。运行期间临时保持电脑唤醒，结束释放，未修改长期电源设置。

额外的分配对照使用 `com.sun.management.ThreadMXBean.getThreadAllocatedBytes` 读取工作线程分配字节差值，每版本预热 1,000 次、正式 2,000 次。数据构造和预热不进入分配统计，统计包含 generate 和轻量结果消费，不包含所有 JVM/GC 线程的分配。原始文件保存在 `target/output-round1-benchmark/`。

## 实测结果

每个版本三轮，各轮独立 JVM、10,000 次正式请求；执行顺序为 before-1、after-1、before-2、after-2、before-3、after-3。全部轮次 checksum 均为 475000。

| 轮次 | 请求/秒 | P50 ms | P95 ms | P99 ms | max ms | GC 次数 / 累计 ms |
|---|---:|---:|---:|---:|---:|---:|
| before-1 | 49.37 | 82.42 | 116.28 | 143.28 | 272.35 | 170 / 3716 |
| after-1 | 161.83 | 24.92 | 30.64 | 36.15 | 101.80 | 154 / 1133 |
| before-2 | 141.32 | 28.36 | 36.06 | 42.18 | 103.86 | 170 / 1326 |
| after-2 | 149.33 | 26.31 | 34.75 | 53.26 | 1148.30 | 154 / 1200 |
| before-3 | 130.35 | 32.06 | 36.39 | 42.13 | 49.77 | 170 / 1404 |
| after-3 | 146.27 | 28.41 | 32.53 | 38.44 | 52.77 | 154 / 1271 |

各版本三轮指标的中位数：QPS 130.35 → 149.33（+14.56%），P95 36.39 → 32.53 ms（-10.60%），P99 42.18 → 38.44 ms（-8.86%）。这是各轮统计量的中位数，不是合并 30,000 条延迟后的分位数。

环境波动明显：before-1 比同版本另两轮慢得多，after-2 有 1148.30 ms 的最大延迟且 P99 高于 before-2。当前数据没有确定这些波动的原因，也不能证明每轮尾延迟都改善；全部轮次保留，不将首轮约三倍吞吐差异当作代码收益。优化后 QPS 范围 146.27–161.83，优化前 49.37–141.32。受桌面机器环境影响，中位数变化只作为本机观测。

分配对照：before 每请求 43,453,509.53 bytes（41.44 MiB），after 每请求 39,390,741.53 bytes（37.57 MiB），减少约 4,062,768 bytes（3.87 MiB，9.35%）。两版本各 2,000 次请求，checksum 均为 95000。该结果来自工作线程分配计数，不是结束时堆占用，也不是 JFR 采样估计。

三轮对照后再次运行 `mvn -q -Dtest=OutputConstructionTest test` 通过。供其他 AI 复跑的任务说明见 [性能测试复现 prompt](performance-reproduction-prompt.md)。
